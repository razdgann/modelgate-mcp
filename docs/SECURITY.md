# Security and threat model

## Assets

1. The ModelGate API key. It grants inference (which spends money) and read access to one
   project's usage and request metadata.
2. Tenant boundaries between ModelGate projects.
3. Prompt and response content passing through the server.
4. The host running the server, especially in remote mode.

## Trust boundaries

- **MCP client → server:** tool arguments are untrusted. They are generated by a model and may be
  shaped by prompt injection.
- **Server → ModelGate:** ModelGate is the authority for authentication, scopes, tenant isolation
  and guardrails. Its responses are validated before use.
- **Remote callers → HTTP server:** unauthenticated network input.

## Threats and mitigations

| Threat                                      | Mitigation                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Key leakage through logs, errors or results | Keys are registered for exact-value redaction at startup. Pattern redaction covers `mg_…`, bearer tokens and `sk-`/`AIza` keys in every log line and error message. Sensitive field names are masked. The key is never put in a result. Tested in unit, integration and e2e suites.                                                       |
| Stack traces or internals reaching clients  | Unknown errors become `internal_error` with a generic message. Upstream error bodies are reduced to documented primitive fields.                                                                                                                                                                                                          |
| Cross-tenant access                         | Every ModelGate call runs with exactly one key, and ModelGate scopes all data by that key's project. The server has no cross-project data path. In remote passthrough mode each request uses the caller's own key and no key is held server-side. Another project's request id returns `not_found` (ModelGate gives no existence oracle). |
| Over-privileged integration credentials     | Scoped keys: MCP clients use `inference:write` plus read scopes, never `admin`, so a leaked MCP key cannot mint keys or change provider credentials. ModelGate enforces this; the adapter does not.                                                                                                                                       |
| SSRF through `MODELGATE_BASE_URL`           | The URL is operator config only and no tool argument can change it. It must be https (http only for loopback), with no credentials, query, fragment or path. Redirects are refused (`redirect: "error"`), so the key never goes elsewhere. Remote mode needs `MODELGATE_ALLOW_CUSTOM_BASE_URL=true` for a non-default origin.             |
| Path injection into ModelGate URLs          | Request ids must match `^[A-Za-z0-9_-]{8,64}$` and are URL-encoded. Model ids, providers and filters are constrained by schemas.                                                                                                                                                                                                          |
| Malicious or oversized inputs               | Strict schemas cover roles, types, enums, and sizes of messages, parts, tools, schemas and metadata, plus a total-size cap. Nothing is passed through as arbitrary JSON beyond JSON-schema objects, which are size-limited.                                                                                                               |
| Prototype pollution                         | Metadata keys are validated, `__proto__`/`constructor`/`prototype` are dropped, and redaction skips them too. ModelGate also clamps metadata server-side.                                                                                                                                                                                 |
| Unbounded upstream output                   | JSON bodies are capped at 10 MiB, error bodies at 64 KiB, and SSE events at 1 MiB. Assistant text returned to the client is capped by `MODELGATE_MAX_OUTPUT_CHARS`.                                                                                                                                                                       |
| Log injection                               | Logs are JSON-serialized, one record per line, so caller text cannot forge records. Content is not logged unless explicitly opted in.                                                                                                                                                                                                     |
| stdout corruption (stdio)                   | The logger writes only to stderr, and ESLint forbids `console`. An e2e test asserts that every stdout line is JSON-RPC.                                                                                                                                                                                                                   |
| Duplicate billable executions               | Inference is retried only when no provider can have been reached (a 429, or a connection that never opened). See the retry policy in the README.                                                                                                                                                                                          |
| Runaway cost after cancellation             | MCP cancellation aborts the upstream fetch, and ModelGate aborts the provider call (logged as `CANCELLED`).                                                                                                                                                                                                                               |
| Environment dumping                         | The config summary (`describeConfig`, the `modelgate://integration` resource, `check`) lists only non-secret fields.                                                                                                                                                                                                                      |

## Remote mode

- The server is never an unauthenticated proxy: every `/mcp` request needs a bearer credential.
  - **passthrough** (default): the token must be a ModelGate key, and it is checked against
    `GET /v1/me` before use. Results are cached by hash, never by the key itself: valid for
    5 minutes, invalid for 30 seconds. Every upstream call still goes through ModelGate's own key
    check, so revoking a key takes effect immediately at the gateway.
  - **token**: shared client tokens of at least 32 characters, compared in constant time against
    SHA-256 digests. Upstream calls use the server's `MODELGATE_KEY`. Use this only for
    single-tenant deployments.
- DNS-rebinding protection validates `Host` against `MODELGATE_MCP_ALLOWED_HOSTS`, which is
  required for non-loopback binds. `Origin` is validated for browser clients.
- Rate limits: per caller (default 120/min), plus 30 failed authentications per minute per IP.
  At most 256 requests in flight; requests beyond that get 503.
- Bodies are limited to 1 MiB by default (413 above that), and headers must arrive within 30 s.
- Responses set `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`.
- Terminate TLS in front of the server. The server does not serve TLS itself.

## Known limitations

- The in-memory rate limiter is per process. Behind several replicas, enforce limits at the
  proxy, or rely on ModelGate's per-key rate limits (which are always enforced).
- The key-verification cache means a revoked key can still open MCP requests on a remote server
  for up to 5 minutes. Every ModelGate call it makes during that time is rejected.
